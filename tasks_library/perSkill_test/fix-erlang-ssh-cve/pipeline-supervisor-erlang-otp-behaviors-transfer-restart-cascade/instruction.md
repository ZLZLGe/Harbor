`/app/workspace/apps/pipeline/src/pipeline_sup.erl` 里提供了一个批处理管线的顶层监督树。

当前实现有恢复编排问题：worker 在处理某些任务时会崩溃，consumer 会跟着退出，但 supervisor 没有按依赖关系把调度链路一起重建，导致 scheduler 继续把调度消息发给旧的 consumer，后面的队列永久堆住。另外，重启参数也需要和这条恢复链路匹配，不能让一次可恢复的崩溃把整棵树拖进重启风暴。

请直接修复提供的 Erlang 代码，保证下面这些语义成立：

- 批处理队列中的普通任务必须被正常消费。
- 当 worker 首次处理 `{crash_once, Name}` 任务时会故意崩溃；恢复后，这个任务和后续任务仍然必须继续完成。
- 发生这类崩溃后，worker、consumer、scheduler 都必须被重建到一致的运行链路，队列里不能留下永远无人处理的积压。
- 恢复完成后继续投递的新任务也必须还能被处理，顶层 supervisor 不能因为这次恢复直接退出。

只需要修改现有代码，不需要改测试，也不需要新增别的服务。
