你接手的是一批已经切好的局地余震三分量窗口，数据来自混合台网，既有强震/短周期记录，也有高增益与非标准分量命名的台站。

输入位于 `/root/campaign/`：

- `/root/campaign/trace_manifest.csv` 列出了本批次全部 `trace_id`、窗口文件相对路径、台站分组与通道信息。
- 每个窗口文件都是 `.npz`，至少包含：
  - `data`: 波形数组，长度固定为 12000 个采样点
  - `dt`: 采样间隔（秒）
  - `channels`: 原始通道名
- 这批窗口没有提供任何模板先验。

你的任务是为 manifest 中的每条记录各输出 1 个 P 拾取和 1 个 S 拾取，并把结果写到 `/root/mixed_network_picks.csv`。

输出 CSV 必须包含且只需包含以下 5 列：

1. `trace_id`: 与 manifest 中一致
2. `phase`: `P` 或 `S`
3. `pick_idx`: 对应相位的采样点索引
4. `confidence`: 0 到 1 之间的浮点数
5. `method`: 该条记录采用的拾取路线标签

额外要求：

1. 每个 `trace_id` 必须恰好对应两行输出：一行 P，一行 S。
2. 同一条 `trace_id` 的 P 和 S 行必须记录同一个 `method`，因为它们来自同一条处理路线。
3. 这批数据混合了多种台站类型，`method` 列中必须实际体现至少两种不同路线，而不是整批都写成同一个标签。
4. `pick_idx` 必须是窗口内索引。
5. 为了得到较高质量的结果，你需要根据波形条件决定什么样的自动拾取路线更适合不同分组，而不是把所有记录都当成同一种台站来处理。

评测重点不是单纯文件格式，而是：

- P/S 拾取误差是否足够小
- 混合台站分组下是否真的做了路线区分
- 输出是否完整且自洽
