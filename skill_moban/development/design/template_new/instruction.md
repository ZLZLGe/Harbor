你需要为城市微出行运营团队制作一份可直接在浏览器中播放的高质量 HTML 演示文稿，用于 5 分钟的季度运营复盘。输入数据包含真实风格的站点状态、车辆可用性、天气事件、投诉摘要和品牌约束；其中一部分数据来自本地运行的业务 API。

输入数据在：

- `/root/data/briefing/operations_snapshot.json`
- `/root/data/briefing/station_events.csv`
- `/root/data/briefing/customer_complaints.jsonl`
- `/root/data/briefing/brand_tokens.json`
- `http://127.0.0.1:8111/api/weather-impact`
- `http://127.0.0.1:8111/api/service-zones`

你的任务：

1. 读取全部输入数据，制作一份单文件 HTML 演示文稿，保存到 `/root/output/presentation.html`。
2. 演示文稿必须面向非技术管理层，清楚说明：
   - 本季度整体运营状态；
   - 可用车辆不足最严重的区域；
   - 天气事件对服务可用性的影响；
   - 客诉主题与运营指标之间的关系；
   - 下一季度的 3 条可执行建议。
3. 演示文稿必须包含 8 到 10 页 slide，每页内容应能在一个浏览器视口内完整显示，不能依赖页面内部滚动阅读。
4. 至少包含以下 slide 类型：
   - 标题页；
   - 执行摘要页；
   - 关键指标页；
   - 区域对比页；
   - 天气影响页；
   - 客诉主题页；
   - 建议路线图页；
   - 结尾页。
5. 至少包含 3 个基于输入数据生成的可视化元素，例如柱状图、趋势图、区域对比图、矩阵图或标注式统计图。可视化必须来自输入数据，不能只画装饰图形。
6. 必须使用 `/root/data/briefing/brand_tokens.json` 中给出的品牌颜色、字体偏好和语气约束，但可以在保证可读性的前提下做合理扩展。
7. 演示文稿必须支持：
   - 键盘左右方向键翻页；
   - 鼠标滚轮翻页；
   - 触摸滑动翻页；
   - 当前页码或进度指示；
   - `prefers-reduced-motion` 降低动效；
   - 无网络环境下直接打开运行。
8. 每页 slide 必须使用语义化结构表达，不能把全部内容渲染成一张不可访问的大图片。
9. 输出必须是自包含 HTML 文件，CSS 和 JavaScript 应写在同一个 HTML 文件内。除输入数据目录外，不得要求外部 CDN、远程字体或在线脚本。

输出格式：

- 必须创建 `/root/output/presentation.html`
- HTML 文件必须能通过本地浏览器直接打开。
- HTML 中应包含清晰的 slide 结构，每页 slide 建议使用独立的 `<section>` 元素。
- 不需要提交额外说明文档、截图或压缩包。

说明：

- 你可以编写辅助脚本来读取、汇总和转换输入数据，但最终交付物必须是 `/root/output/presentation.html`。
- 可以对数值做四舍五入和摘要，但不得改变指标含义。
- 如果不同数据源之间存在轻微冲突，应在演示文稿中采用可解释的聚合口径，而不是删除冲突数据。
- 设计应专业、清晰、有演示感，但不要做成营销落地页、仪表盘应用或普通长网页。
- 禁止修改、删除或替换输入数据。
- 禁止删减功能来规避布局、动效或响应式问题。
