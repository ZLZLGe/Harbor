# debugging类模板任务

## 任务元数据
- 类别：`debugging`
- 模板类别：`repo-runtime-env`
- 描述：该目录用于定义仓库运行时类模板任务。重点是复用代码仓库、语言运行时、build/test toolchain、配置源和环境状态这一套统一环境骨架。

## 场景说明
- 这类任务通常围绕编译失败、测试失败、打包失败、依赖冲突、CI 回归、配置漂移、环境变量错误或 Feature Flag 错配展开。
- 维护者优先复用代码仓库、构建命令、测试入口、配置文件和运行态开关，而不是每次重新设计环境。
- 模板重点是让失败能稳定重现，并且让修复必须落在真实仓库执行路径上。

## solver 输入面
- 可见输入通常包括：仓库代码、失败日志、构建脚本、测试命令、配置文件、环境变量说明、开关状态或路由规则。
- instruction 只描述失败现象和约束，不直接给出修复点或具体错误配置。
- 不可见输入通常包括：维护侧补充说明、发布记录、额外参考 patch、隐藏验收脚本细节和内部状态信息。

## 环境设计
- Docker 基座通常复用项目语言运行时、包管理器、build tool、test tool、配置文件和必要的环境变量注入。
- 服务拓扑通常是单仓库单入口，也可以附带一个最小 CI 风格执行环境或一个隐藏配置源/状态服务。
- 核心工具链应围绕 build/test 命令、依赖安装、配置比对、状态切换和失败日志展开，减少无关环境差异。

## Verifier 设计与合理性
- 主测试应检查构建、测试、打包或目标配置路径已经恢复，关键行为与预期一致。
- 防作弊测试应拦截跳过测试、删除失败用例、绕过真实构建入口、替换关键依赖、硬编码返回值、跳过开关判断这类伪修复。
- 这类 verifier 重点是保住真实仓库执行路径和失败入口，而不是让任务退化成补丁外形匹配。

## skill 与任务强相关性
- 这类模板与构建排障、CI 修复、依赖定位、配置排查、开关验证和环境差异定位类 skill 强相关。
- 维护者复用这一类模板时，主要复用的是 repo 执行骨架、build/test 环境和配置状态。

## 模板任务结构分类
- `README.md`
  当前模板规范说明。
- 建议后续补齐：`instruction.md`
  只放失败现象、环境范围、业务约束和禁止事项。
- 建议后续补齐：`environment/`
  提供稳定的 build/test toolchain、配置源、环境变量和失败入口。
- 建议后续补齐：`tests/`
  主测试与防作弊测试。
- 建议后续补齐：`solution/`
  简洁的参考修复。
- 建议后续补齐：`validation/`
  维护侧验证材料。
