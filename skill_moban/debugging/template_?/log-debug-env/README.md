# debugging类模板任务

## 任务元数据
- 类别：`debugging`
- 模板类别：`log-debug-env`
- 描述：该目录用于定义日志排障类模板任务。重点是复用日志样本、事故样本和日志分析工具这一套环境骨架。

## 场景说明
- 这类任务通常围绕报错频发、链路异常、事故复盘不一致和 session 级异常排查展开。
- 维护者优先复用日志样本、错误样本、事故摘要和日志分析工具，而不是单独重搭一套新环境。
- 模板重点是让问题通过真实日志信号暴露，并保留可重复排查的路径。

## solver 输入面
- 可见输入通常包括：应用代码、日志片段、错误样本、事故摘要和时间范围。
- 输入面重点是让 solver 看到足够的日志证据，但不直接暴露完整根因。
- 如有隐藏上游或内部补充材料，继续保留在维护侧，不直接给 solver。

## 环境设计
- Docker 基座通常复用代码仓库、日志样本目录和基础分析工具。
- 服务拓扑可以是单仓库加日志包，也可以带一个隐藏服务或回放器。
- 核心工具链应围绕日志筛选、错误定位和时间线分析展开，避免为每个任务单独换工具体系。

## Verifier 设计与合理性
- 主测试应检查故障是否真正修复，例如关键错误消失、正确链路恢复、目标日志状态更新。
- 防作弊测试应拦截删日志、绕开真实链路、替换数据源、简单吞错这类伪修复。
- 这类 verifier 重点仍然是保住真实日志路径，而不是只看补丁形状。

## skill 与任务强相关性
- 这类模板与日志排查、事故定位、错误归因类 skill 强相关。
- 维护者复用这一类模板时，主要复用的是日志环境骨架和分析工具链。
